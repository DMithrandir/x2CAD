# ADR-0001：NURBS 数学核心先行，B-Rep 拓扑变异不由 AI 直写

- 状态：已接受
- 日期：2026-08-24
- 决策人：用户（方向指令）+ 主会话（落地）
- 关联：`docs/plans/2026-08-20-x2cad-kernel-design.md` §8/§10/§11

## 背景

AI（LLM）在两类代码上的错误模式有本质差异：

1. **纯数学叶子算法**（基函数、求值、求导、插值、节点操作）：定义有教科书级规范、
   行为有解析真值与不变量。错误**可被强预言机当场捕获**（单位分解、|C(u)|=1、
   有限差分、往返恢复），修复回路闭合。
2. **B-Rep 拓扑结构变异**（布尔运算中的边/面/壳重建、非流形修复、拓扑事件排序）：
   正确性散布在大量隐性不变量（每条边恰好 1/2 个邻接面、方向一致性、
   Euler-Poincaré 特征）与状态机顺序上。错误**潜伏于深层状态组合**，
   局部测试很难在写码时刻捕获，AI「脑补」出的拓扑代码几乎必然带隐性 bug。

## 决策

1. **实施顺序重排**：NURBS 数学核心（原 P3 的曲线部分）提前为首个人工可验收的
   落地阶段（N1）；2D/网格 BRep 阶段（原 P1/P2）中一切**拓扑结构变异代码不由
   AI 直接成文**——改为：规格先行 + 人审查的分步小实现，或封装参考实现
   （manifold3d / OCCT），AI 只承担其中可独立验证的叶子算法（谓词、分类、
   数值核心）。
2. **预言机内嵌**：每个数学算子交付时必须自带四路 oracle 测试——
   解析真值（圆不变量、Bézier 闭式）、独立参考实现对拍（原始 Cox-de Boor 递推）、
   有限差分（求导类）、不变量（单位分解、残差、往返恢复）。测试红 = 代码错或
   测试错，二选一修，禁止放宽断言了事。
3. **双实现互拍**：易错的核心路径提供两条独立推导路线（基函数导数 vs 控制点
   差分链；齐次坐标 + Leibniz 投影 vs 有限差分），一致性本身是预言机。
4. **退化显式化**：重数/光滑度不足、重复数据点、奇异系统一律 `DomainError`
   拒绝（S/N 族语义），不允许静默扰动或吞错。

## 后果

- 正面：首个可用内核增量（求值/求导/插值）即刻落地；B-Rep 阶段的 AI 风险面
  被显式隔离；退化语义在数学层先成熟，未来拓扑层直接复用。
- 负面：拓扑里程碑时间后移；参考实现封装引入外部依赖（pythonocc/manifold3d）。
- 修正记录：初版测试中「多项式重现」用例构造错误（数据采样参数与插值参数
  不一致），实现无误——预言机同样会抓测试的错，这正是要的效果。
