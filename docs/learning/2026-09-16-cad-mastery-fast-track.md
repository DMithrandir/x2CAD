## 1. 心智模型：CAD 内核一张图（Day 1 上午，约 1.5h）

### 1.1 先用 30 分钟亲手建一次模（免费工具 FreeCAD 或 Fusion360）

做：草图（矩形 + 圆角）→ 拉伸成块 → 选一条边倒圆角 → 布尔差挖一个孔。带着四个观察回来：

1. **所有操作都发生在「选实体」上**：选边才能倒角、选面才能拉伸。这就是 Pointer-CAD 文档
   说的「实体可引用」——也是我们内核未来的 EntityRef 层的用户侧根源。
2. **每个操作产出新模型状态**，不是覆盖旧的。
3. **倒角/圆角最容易出错**：选错边、半径过大导致自交、相邻边连锁变化。
4. 软件里撤销/重做是建模的一部分——实体 id 的稳定性是这一切的底座。

### 1.2 B-Rep 心智模型（三个概念就够）

| 概念 | 一句话 | 在本项目里的位置 |
|:--|:--|:--|
| **几何 vs 拓扑分离** | 几何 = 形状（点坐标、曲线曲面方程）；拓扑 = 连接关系（顶点-边-面-壳-体）。一条边可指向同一条曲线几何 | 母文档 §3.1 内核层；P2 网格 BRep |
| **欧拉特征** | 闭流形 V − E + F = 2(1−g)（球 g=0 时 =2），是「模型没坏」的恒等式 | 验证台 Tier 1（母文档 §6.1） |
| **容差** | 现实中不存在「恰好重合」，只有「容差内重合」；CAD 80% 的成本在退化几何 | 母文档 §5 五族退化知识库 |

### 1.3 NURBS 心智模型（同样三个概念）

1. **曲线 = Σ 基函数 × 控制点**：控制多边形是「操纵杆」，移动控制点曲线跟着动；
   基函数决定每个控制点的影响范围。不用背公式——公式全部在 `spec.json` 的 `source` 字段里
   按需查（式 2.5/2.6/2.7、算法 A2.1–A2.3、A3.2–A3.4、A4.4、A9.1）。
2. **参数 u 是曲线的「进度条」**；节点向量（knots）决定基函数的影响区间。clamped 节点向量
   = 两端重数 p+1，保证曲线端点恰好落在首末控制点上。
3. **Bézier 是特例，圆弧是 NURBS 的精确成员**：Bézier = 无内部节点的样条；圆弧 = 带权的
   二次有理曲线（`tests/test_rational.py` 的圆不变量就是在验证这一点）。

> 十分钟直觉练习：用 matplotlib 画一条 p=3 的曲线 + 控制多边形（约 15 行脚本，用
> `operators/curve_eval/impl.py` 的 `curve_point`），拖动一个控制点看曲线怎么变。这一步
> 建立的直觉比读十页公式值钱。

**关键认知**：仓库里「AI 生成的部分」仍严守 ADR-0001 的边界——纯数学叶子算法 + 可静态
验证的脚手架。新增的两类东西值得单独理解：

1. **验证台（`verify/`）不是测试的重复**：它把「什么算对」写成可复跑的证据（不变量、
   解析真值、鲁棒性平面、变异捕获率），并用 `python -m verify` 变成门禁；
2. **契约（`kernel/entity_ref.py`）不是实现**：它先冻结「实体如何被引用、变异后引用何去
   何从」，让后续布尔/倒角不在表示层返工（Pointer-CAD 的核心教训）。

流水线（ref2spec/spec2op）仍只有设计；`tests/` 里现在有 `test_mutation_audit.py` 这类
「验证验证台」的元测试，读它比读任何单个算子更能理解本项目的纪律。

## 4. AI 与人的分工难点（随时回看的核心认知章）

> 这里回答「为什么 ADR-0001 要划那条红线」。理解这些难点，比会写任何一段算法都重要。

### 4.1 六个难点

1. **LLM 的错误会「延迟爆发」**。数学叶子算法的错当场被抓（定义有教科书级规范、行为有解析
   真值）；B-Rep 拓扑变异的错（布尔中边/面重建、非流形修复、拓扑事件排序）潜伏在深层状态
   组合里，写代码的那一刻任何局部测试都抓不住——AI「脑补」出的拓扑代码几乎必然带隐性 bug。
   → 这就是「拓扑变异不由 AI 直写」的根本原因，不是 AI 不够强，是**错误的可观测性**不同。

2. **几何代码的正确性无法目测**。数值结果没有「看起来对」，唯一判据是 oracle。所以：验证台
   先于内核（预言机先于被验者）；且 **oracle 必须来自独立推导路线**——用被测代码自身的输出
   做 oracle 等于没测（`test_curve.py` 的有限差分基于同库 `curve_point`，是弱 oracle，必须有
   Bézier 闭式、端点差分闭式这些强 oracle 配对）。

3. **预言机本身也会错，而且会「放水」**。ADR-0001 修正记录：初版「多项式重现」用例构造错误
   （采样参数与插值参数不一致），是**测试错、实现对**——预言机同样会抓测试的错，这是对的；
   但另一种腐蚀是 AI 修不动代码时去改断言、放宽容差。→ CLAUDE.md 铁律：断言失败先怀疑被测
   代码与测试构造，再怀疑容差；容差不得随意放宽。

4. **AI 会「脑补」规格里没有的东西**：静默扰动退化输入、吞掉异常返回 None、埋魔法精度数。
   → 所以 spec 四段结构 + `DomainError` 纪律 + 静态检查器红线（裸比较/无分支 pitfall/魔法数），
   把「脑补」变成可被机器拒绝的形状。

5. **真正需要人的地方是语义，不是对错**。「这个结果对不对」可以自动化裁决；「重数节点处
   该给单侧值还是拒绝」「两个合法规格冲突时选哪个」是语义选择，没有客观答案。→ HITL 只放
   三处闸门（容差裁决 / API 冻结 / unhandled 确认），其余全自动。人被问的永远是「语义选哪个」，
   不是「这个对不对」。

6. **表示设计决定能力上限，而表示设计必须人先定**。Pointer-CAD 证明：序列表示不可引用实体，
   于是倒角/圆角在该表示下**根本不可表达**——模型再强也没用。X2CAD 的对应物：EntityRef 引用层、
   重编号契约、spec schema 这类横切设计，必须现在由人定死，否则 P2 之后每个算子返工。
   **人的价值在于把隐性约束显式化，AI 的价值在于在显式约束内快速试错。**

### 4.2 分工表（当前生效版）

| 任务类型 | 谁做 | 为什么 | 风险等级 |
|:--|:--|:--|:--|
| 纯数学叶子算法（求值/求导/插值/节点操作） | AI 直写 + oracle 裁决 | 教科书级规范，错误当场可抓 | 低（须四路 oracle 全绿） |
| 脚手架/静态检查器/测试代码 | AI 直写 | 可静态验证 | 低 |
| B-Rep 拓扑结构变异（布尔/修复/拓扑事件） | **规格先行 + 人审查分步实现，或封装参考实现（manifold3d/OCCT）** | 错误延迟爆发，局部测试不可观测 | 高（AI 直写） |
| 容差语义 / 退化行为裁决 | 人 | 语义选择，无客观答案 | — |
| 公共 API 装配（kernel/） | 人（API 冻结闸门） | 签名即承诺，改签名要全盘返工 | — |
| 引用层/重编号契约等横切设计 | 人定契约，AI 实现叶子部分 | 表示决定能力上限 | — |

**一句话总结分工难点**：难点不在「谁写哪行代码」，而在「谁对正确性负责」——AI 负责在显式
约束内生成候选，**预言机负责裁决**，**人负责语义与边界**。任何一环越界（人替 AI 做几何计算、
AI 替人做语义裁决、预言机被人绕过），项目就会在对应的地方腐烂。
