## 参考答案与验证

> 数值全部由仓库代码实测（Python 3，2026-09-16）。做完全部题目再往下翻。

### A 组答案

**A1.1** span=4；二分路径 lo=2,hi=5 → mid=3(u≥U[4]→lo=3) → mid=4(返回)。
基函数 = [0.125, 0.625, 0.25]，Σ=1.0。手算关键步：N_{3,1}=0.5、N_{4,1}=0.5，
再合成 N_{2,2}=0.125（右项 (3−2.5)/2·N_{3,1}）、N_{3,2}=0.375+0.25=0.625、
N_{4,2}=0.25。

**A1.2** span=3，基函数 = [0.5, 0.5, 0.0]，Σ=1.0，无 NaN。零分母项：
r=1 右项分母 U[5]−U[4]=0，配对的 N_{4,0} 支撑是 [U[4],U[5]]=[1,1]（退化点，
恒 0）；r=2 右项分母 U[6]−U[4]=0，配对的 N_{4,1} 支撑 [U[4],U[6]]=[1,1]
同样退化。惯例安全。

**A1.3** find_span 特判返回 n=4；基函数 [0.0, 0.0, 1.0]，Σ=1.0；u=3−1e-9 时
[5e-19, 2e-9, 1.0]。若按朴素右连续，N_{i,0}(3)=0 全灭、ΣN=0，曲线端点会
返回原点——所以必须取左极限（把 u 按 span=n 处理），C(U[n+1])=Pₙ 才成立。

**A1.4** ξ = [0.0, 0.5, 1.5, 2.5, 3.0]；线性精度实测最大误差 4.4e-16。
恒等式 Σ N_i ξ_i = u 意味着「控制点落在 ξ 上的直线」被忠实表示为参数直线。

**A1.5** 各阶导求和 = [1.0, 0.0, 0.0]。Σ N_i(u)=1 对一切 u 恒等，等式两边
逐阶求导：常数的任意阶导为 0。

**A2.1** C(U[p])=(0,0)=P₀；C(U[n+1])=(5,2)=P₄；C'(U[p])=(2,4)=闭式
p/(U[p+1]−U[0])·(P₁−P₀)=2·(1,2)。推导：u=U[p] 处仅 N_{p,p} 非零（值 1），
其导数 = p/(U[p+1]−U[p])·N_{p,p−1} − 0 = p/(U[p+1]−U[0])（clamped 下
U[p]=U[0]），再乘 (P₁−P₀) 差即可得。

**A2.2** 方法 A：C(0.5)=(3,1)=P₂（全重数节点插值控制点：p=2 内部重数 2 时
曲线 C⁰ 穿过 P₂），C'=(4,−4)、C''=(0,24) 为右向单侧值；方法 B 抛 DomainError
（内部重数 2 > p−n_ders=0）。裁决参考：两者都对——A 的「单侧值」是导数
存在性的精确表达，B 的「拒绝」是光滑性前置的诚实表达；语义选择（给单侧值
还是拒绝）正是 HITL 闸门 1 的范畴。

**A2.3** |C(u)|−1 最大偏差 2.2e-16；C(0)=(1,0)、C(1)=(0,1)；C·C'=0.0
（实测精确 0）。中间权 √2/2：二次有理 Bézier 表圆弧时，中间控制点
(1,1) 到圆心距离 √2，权重 = 1/(√2/1)… 更直接：w=cos(θ/2)=cos45°=√2/2。

**A2.4** 解析 C'(0.5) = (−1.17157287525381, 1.17157287525381)；中心差分
误差 8.04e-9 ≈ O(h²)。该 oracle 是**弱**的（差分基于同库 nurbs_curve_point），
由 A2.3 的圆不变量与 Bézier 闭式等强 oracle 兜底。

**A2.5** 权重 ×3 后：最大点差 3.3e-16、最大导差 1.1e-16（机器精度），
`==` 为 False。数学上 A、W 同乘 λ，C=A/w 与 Leibniz 反解各阶导均不变；
浮点上中间量放大改变舍入，末几位 ulp 不同。这正是「几何量禁裸 `==`」红线
的实锤案例。

**A3.1** 三种参数化都精确过点（残差由算子后置检查保证）；二阶导最大范数：
uniform 104.48、centripetal 86.07、chordal 74.48。chordal 按弧长分配参数，
拐角处参数速度均匀，过冲最小。对称数据（等弦长）下三者参数完全一致——
所以测试数据必须不对称。

**A3.2** 中点最大误差 3.3e-16。m+1 个不同参数点的 p 次插值唯一；t+t³ 本身
是 B 样条空间成员（同一节点向量、p=3），解线性系统必然恢复原曲线。

**A3.3** DomainError（「长度为零：重复数据点无法参数化」）。插值语义是
「恰过每个给定点」，静默去重改变了问题本身。

**A3.4** S(0.5,0.5)=(1.0,1.5,1.25)=四角平均；S_u=(0,3,1.5)（=
(1−v)(P₁₀−P₀₀)+v(P₁₁−P₀₁) 在 v=0.5 的值）；S_v=(2,0,1.5)；S_uv=(0,0,1)
=P₀₀−P₀₁−P₁₀+P₁₁。twist 常数，与 (u,v) 无关。

**A3.5** S_uv 解析 (0,0,1) vs 对 S 做 u 向差分 (0, 3.0, 1.5)（这是 S_u 的
差分验证，误差 ~1e-13 量级在 S_u 上）；交换性来自基函数可分离：
S(u,v)=ΣΣ N_i(u)N_j(v)P_ij，混合偏导 = ΣΣ N'_i N'_j P_ij，求导顺序无关
（基函数 C^∞ 光滑、张量积可分离）。

### B 组参考答案

**B1.1** 参考 schema：stage=`ref2spec_L{k}`；version=schema 版本
（提示词改动应视为 schema 升级）；inputs = {doc_hash, 上层输出**哈希** +
本层 focus}——放哈希让键短、可传播失效，代价是追溯时要反向查库；deps =
{operator_schema 版本, 退化索引版本, 模型名}。L0 的 inputs 含全文切片哈希，
L1–L4 含上层层输出哈希（链式失效传播）。

**B1.2** 参考：文档改动→inputs 失效；schema 改动→version 失效；模板改动→
deps 失效；退化语料改动→deps 失效；模型名→deps（或直接不放缓存键、放
metadata，权衡：同输入不同模型结果不同，建议失效）；温度→同模型名，建议
失效或禁止变温；提示词文本→version；oracle 测试→**不进缓存键**（测试变
不代表提取变，但测试变了要重跑验证，那是验证台的事）。

**B1.3** 前缀 = 系统提示+模板+spec+退化上下文（稳定），后缀 = 文档切片+
本次指令；修复轮前缀占比越高，DeepSeek 自动前缀缓存收益越大。与追溯的
矛盾：追溯希望「按时间顺序追加」，前缀缓存希望「可变部分永远在最后」——
取舍：追溯落盘在文件里（reasoning.md），prompt 里的顺序只服务缓存，
两者解耦。

**B1.4** 参考实现要点：`get_or_compute(stage, version, inputs, llm_fn, deps)`
+ 断言 `calls["n"] == 1`（同 tests/test_cache.py 的 `_counting` 模式）。

**B1.5** 无缓存：5 层 + 2 修复 = 7 次 × $0.01 = $0.07。有缓存：首轮 5 次
$0.05 + 5 次盘开销 $0.0025 + 修复轮 2 次命中 $0 → 约 $0.0525。修复轮 ≤1
时（总调用 ≤6）盘开销可能超过省的 $0.01 的一半——但**真正盈亏不在钱**，
在设计文档 §1.2：玩具项目不值得为缓存做复杂失效治理，缓存的价值是
「可审计的幂等重跑」，成本账只是提醒你别过度工程。

**B2.1** 参考估算：L0（全文档扫算子）需最大切片，超 100K 字符即 Mode B；
L1–L3 输入 = 上层层输出（≤2K）+ 本层切片（≤4K）+ 模板，通常 ≤8K token；
L4 需精读公式上下文，切片与 L2 符号表绑定。溢出点几乎总在 L0 与「超大
文档 + 多算子」组合。

**B2.2** 双路 = 正则触发词（tangent/coplanar/coincident/nearly/epsilon/
degenerate/self-intersect…）粗筛 + LLM 语义精排；检索为空 → **注入五族
摘要**（保证 LLM 至少知道五族存在，而不是裸奔）；命中未处置 → 升级
`needs_human_review`，判定规则：spec 的 degeneracy_branches 中无对应条目
或 impl 中无对应分支即升级。

**B2.3** 参考协议：必读 `state.json`（目标、已试方案、当前根因假设、证据
路径）+ 必写 `round-{n}.md`（做了什么、结果、下一步）。对话续传的优势是
上下文热，劣势是漂移与失控增长；文件协议让每轮从零读最小状态，长期记忆
与短期思考物理隔离——这正是 Ralph 的设计。

**B2.4** L0 选**分片+归并**（候选算子检测天然可分片、可并行、按文档结构
切）；L4 选**精读上下文**（容差语义依赖公式邻域，截断会脑补），必要时
只给命中的公式上下文（检索式精读）。两者差异的根：L0 是「召回」任务
容忍切分，L4 是「语义裁决」任务不可切分。

**B3.1** 参考：reasoning.md（消费者=人，字段=复述/不变量/退化清单/自审）；
spec.json（消费者=静态检查器+codegen，字段=五层+L4 容差策略）；impl.py
（消费者=静态检查器+验证台）；evidence/（消费者=验证台+人）；diagnosis_
report.md（消费者=人，字段=规格 vs 实测对照+失败根因假设）。

**B3.2** 参考序列：`[PROGRESS] 生成 impl v1` → `[ARTIFACT] operators/
boehm/impl.py` → `[PROGRESS] 验证` → `[ERROR] 测试 test_x 失败：…` →
`[PROGRESS] 修复轮 1/1` → `[ARTIFACT] …` → `[PROGRESS] 再验证通过` →
停。静默循环 = 连续 N 次改动而无 [ARTIFACT]/[ERROR] 可见产出、或同类
失败重试超过 3 次不报。

**B3.3** 状态机：生成 → 验证 →（失败且同类错误 <3）修复 → 验证 →（同类 ≥3
或修复轮 >1）停止并产出根因假设。错误聚类：按「失败测试名 + 退化族标签」
两元组聚类；计数在**换算子或换错误类别**时复位，换类别不换算子不复位。

**B3.4** 容差放宽 → 闸门 1（人裁决，产物 hitl_review.json）；API 冻结 →
闸门 2（人，记录到 ADR/API 契约）；unhandled pitfall → 闸门 3（人确认）；
测试全绿 → 不进闸门（预言机已裁决）；两规格冲突 → 闸门 1。核心原则：
「对不对」不进闸门，「语义选哪个」才进。

**B3.5** 八条红线示例（每条配 bug 例）：① 几何量裸 `==`（A2.5 的 3.3e-16
实例）；② 魔法精度数（1e-13 主元判据写死）；③ pitfall 无分支（spec 声明
相切处理，impl 无对应代码）；④ 吞异常返回 None（静默降级）；⑤ 缺后置
不变量（插值算子无残差检查）；⑥ 算子间 import 实现（curve_eval import
surface_eval 内部函数）；⑦ 全局可变状态（模块级缓存字典无锁）；⑧ 算子
内 IO（读文件/打印）。层间白名单用 AST 检查 impl 的 import 语句前缀是否
∈ {primitives, 标准库}，直接可静态验证。

**B3.6** 参考框架：8 步表，每步列（输入 → 输出 → 缓存键 → 追溯产物 →
失败去向）。做完对照母文档 §4，常见的遗漏是：parse 层的文档哈希没进 L0
的 inputs、诊断步没有独立缓存键（诊断必须随验证重跑，不应缓存！）、
失败分支缺少「HITL 闸门」路由。
