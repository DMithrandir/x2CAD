## 0. 统一心智模型（先读三分钟，再动手）

这个仓库的全部纪律可以压缩成一句话：**LLM 产出候选，预言机裁决对错，人管语义**。
三件套是这句话里「LLM」那一侧的工程化：

| 三件套 | 一句话 | 如果不做 |
|:--|:--|:--|
| 产物缓存 | 不给不可信输出付两次钱 | 修复轮反复重算未变的层，烧 token 烧时间 |
| 上下文内存管理 | 不让不可信输出在上下文里堆积 | 上下文溢出 → 模型「脑补」规格里没有的东西（主路线 §4 难点 4） |
| CoT 追溯 | 不让不可信推理蒸发掉 | 出错时无从定位断点，只能改「看起来可疑」的代码 |

它们与 oracle 是同一个命题的三个面：**不信任的工程化**——不是「让模型更强」，而是
「让模型的输出变便宜、变干净、变可审计」。

## 1. 产物缓存与失效纪律（教材：`x2cad/cache.py` + `tests/test_cache.py`）

### 1.1 读代码（30 分钟）

1. 跑 `python -m pytest tests/test_cache.py` 确认全绿——先红绿见证，再读实现。
2. 通读 `x2cad/cache.py`，逐条对照它 docstring 里的 5 个学习点，每个都要能说出
   「为什么这样设计」：

| 学习点 | 为什么 |
|:--|:--|
| key = sha256(规范 JSON(stage, version, deps, inputs)) | 内容寻址：输入变 → 键变 → 自然失效，不存在「忘清理」问题 |
| 规范 JSON（sort_keys） | 同一 dict 键序不同必须是同一键——有测试钉死 |
| version / deps 进键 | 模板版本、退化语料版本是**输入之外的真相源**，必须显式纳入失效 |
| 原子写（tmp + os.replace） | 崩溃不留半截产物，否则下次载入损坏文件 |
| 损坏即 CacheError | 「静默重算」看似无害，实则会掩盖「缓存已被污染」这个事实——同 `DomainError` 纪律 |

3. 通读 `tests/test_cache.py`：注意 `test_same_inputs_compute_once` 的断言
   `calls["n"] == 1`——**「第二次 0 次 API 调用」是被测试证明的，不是嘴上说说**。

### 1.2 练习（30 分钟）

1. **手推一次 key**：取 `STAGE/VERSION/INPUTS`，在 Python 里手动
   `json.dumps(envelope, sort_keys=True, separators=(",", ":"), ensure_ascii=False)`
   再 sha256，与 `cache.key(...)` 输出逐字符一致。
2. **写失效矩阵**（本课第一份产出）。列 4 个变化源 × 是否该失效 × 为什么：

| 变化源 | 是否失效 | 理由 |
|:--|:--|:--|
| 输入文档改动（doc hash） | 失效 | 内容寻址自然覆盖 |
| 算子模板版本 bump | 失效（version） | 代码生成器的行为变了 |
| degeneracy 语料更新 | 失效（deps） | 注入的修复上下文变了 |
| 模型/API 版本更换 | **建议失效** | 同输入输出可能不同；讨论：若把模型名放进 key，会失去什么？ |

3. **模拟一次「生成 + 修复轮」**：用 `_counting` 包一个假的 LLM 函数，跑
   `get_or_compute` 两次（第二次模拟修复轮重发同一 spec），打印 hits/misses
   与「省掉的调用次数」。这就是 §4.4 有界重试的成本账本。

### 1.3 验收

能不看代码回答：**为什么「缓存规则」和「失效规则」必须成对出现？** 给一个
「只写缓存、不写失效」的具体翻车场景（提示：模板改了、缓存没清，新算子带着
旧模板的 bug 生成——而测试全绿，因为测试也是旧模板写的）。

## 2. 上下文内存管理（教材：母设计文档 §4.1 / §4.2 / §4.4 / §7.1）

### 2.1 教材点（母文档里早有，只是没叫这个名字）

| 母文档条款 | LLM 工程术语 | 一句话 |
|:--|:--|:--|
| §4.1 Mode A（≤100K 字符，头+尾截断）vs Mode B（语义检索） | 上下文窗口管理 | 装得下就装，装不下就检索 |
| §4.1 五层串行、每层只带上层结构化 JSON | 分层状态压缩 | 每步输入小到错误当场可抓（「错误被逐层截断」） |
| §4.2 degeneracy 只注入命中的几条 | RAG 工作集 | 上下文里只放本次任务相关的 pitfall |
| §7.1 Ralph「工作区文件为持久记忆，每轮新上下文」 | agent 记忆架构 | 长期=文件，短期=上下文 |
| §4.4 有界重试（至多一轮修复、同类错误 3 次） | 循环预算 | 上下文/预算双上限，禁止无限打补丁 |

### 2.2 练习（30 分钟）

1. **token 预算表**（本课第二份产出）。以「对 NURBS Book A5.1 做五层提取」为
   例，逐层估算 prompt 构成（系统提示 ~500、算子模板 ~800、上层层输出累积、
   文档切片大小），标出哪一层会逼近/超过预算，写出 Mode B 的接管条件。
   没有真实 API 也照做——估算是这课的本体。
2. **重新归因一次「脑补」**：主路线 §4 难点 4 说 AI 会脑补规格里没有的东西
   （静默扰动、吞异常、魔法数）。读完本节后，用「上下文超载 + 没有 schema 约束」
   重新解释一次它为什么会发生，并说出本仓库的对策为什么是**结构**（五层 schema、
   四段模板、静态检查器）而不是「换个更强的模型」。

### 2.3 验收

画出三层记忆图并各指一个仓库实例：**长期记忆（文件）**——`evidence/`、`degeneracy/`；
**短期记忆（上下文）**——单层提取的 prompt；**工作集（检索）**——degeneracy 注入。
答不上实例就是没读透。

## 3. CoT 追溯（教材：ADR-0001 修正记录 + 主路线 Day 5 checklist）

### 3.1 概念：CoT 当提示技巧是消费，当追溯链才是资产

「让模型分步思考」如果只发生在对话里，答完就蒸发——它是消费。
本项目把每一步思考**落盘成文件**，连成可 grep 的审计链：

```
reasoning.md（复述/不变量/退化清单/自审）→ spec.json（L0–L4）→ impl.py
→ evidence/（四层证据）→ diagnosis_report.md（规格 vs 实测对照）
```

加上 §7.3 的 `[PROGRESS]`/`[ARTIFACT]`/`[ERROR]` 会话级标记协议——禁止静默循环，
也就禁止了「蒸发」。**追溯链的价值不在平时，在断点定位时。**

### 3.2 练习（30 分钟）

1. **追溯完整性检查**（本课第三份产出）：对现有三个算子，任选其一，逐条断言
   找来源——「这条断言对应 spec 的哪条 invariant / 哪个退化分支」，找出至少 1 处
   「断言无来源」或「来源无断言」。这就是主路线 Day 5 checklist 的预演。
2. **复述 ADR-0001 修正记录**：「多项式重现用例构造错误——测试错、实现对」。
   为什么能定位到「测试错」？因为测试构造被记录在案，追溯链找到了断点。
   问自己：如果当时没有记录测试的构造思路，你会去改哪里？改错会怎样？
   （答案：你会去改对的代码，把 bug 藏得更深——这正是追溯的价值。）

### 3.3 验收

能一句话说清：**模型的思考过程不可信，但模型思考过程的持久化形式可以被确定性
检查器消费**——这句话和「LLM 从不被信任直接做几何计算」是什么关系？

## 5. 自测题（验收线：全部能答，答不上留在本课）

- **T0-1** key 为什么必须含 version？给出一个「不含 version」的具体翻车例子。
- **T0-2** 规范 JSON 为什么 sort_keys？两个内容相同、键序不同的 dict 若不 sort 会怎样？
- **T0-3** 缓存文件被篡改后 load 做什么？「静默重算」为什么违反仓库纪律？
- **T0-4** 修复轮为什么天然适合 prompt 前缀缓存？前缀=？后缀=？前缀缓存与本课的产物
  缓存各解决什么问题？
- **T0-5** Mode A 的「头+尾截断」会丢什么？为什么 L0（算子检测，需全文档扫候选算子）
  比 L4 更不能容忍截断？
- **T0-6** 追溯链四环 reasoning / spec / evidence / diagnosis 各回答
  「谁做、做什么、怎么证明对、哪里不对」中的哪一个？
